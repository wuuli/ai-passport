首个设备版本已包含可移植核心、带时间戳的输入、中文 LVGL 页面、设备尺寸像素素材、AI 练习与可选音效。用户已授权直接装机。下表分别记录实现、自动检查和实际设备验收。

## TD-01 实现约定

- 调用方传入整数微秒时间戳，估时四舍五入到毫秒，再比较绝对误差。这是判分分辨率，不代表实际按键具有 1 ms 精度。
- 目标为 1.0～6.0 秒、间隔 0.5 秒。平局保留目标与比分，交换先手，不增加计分回合数。
- 状态全部放在调用方持有的定长结构体中；不分配内存，不创建任务，不执行 I/O，不依赖 ESP-IDF 或 LVGL。
- `duel_clock_init` 初始化到首页。`duel_clock_handle` 接受 OK、周期 TICK、HOME 取消，以及仅首页可用的模式切换。布尔返回值表示可见游戏状态是否变化；返回 false 不代表内部时间戳也完全没变化。
- 时间戳非负，按时间顺序处理。硬件记时必须发生在入队之前；排空输入前先记录本批次时间，处理完输入后用该时间提交 TICK，不能在排空后重新取时间、越过并发入队的按键。早于已处理按键的 tick 可安全忽略；每个输入只处理一次，过期时间戳直接拒绝，不悄悄修改测量时间。
- 未停止的挑战精确截断在目标 + 3 秒，即使轮询到达较晚也不延长成绩。迟到的 OK 只结束当前挑战，不能同时确认交接或继续结算。已接受的 OK 按下之间有 200 ms 防抖。
- 单人模式始终由人类先手。目标和 AI 误差使用相互独立的带种子随机流，AI 不读取人类成绩。误差采用 sigma = 0.12 × 目标时长的高斯分布，截断到 220 ms 至目标 + 2900 ms。
- AI 等待至少 1100 ms。双方完成后进入 SEALED，持续等待 OK，此时尚不计算赢家或加分；确认后只结算一次，进入 ROUND_END。1500 ms 后或按 OK 跳过动画，进入 RESULT；数值成绩持续等待 OK，tick 不能跳过成绩页或自动开启下一回合。
- `duel_clock_view` 是 UI 边界：交接时显示目标，计时阶段隐藏目标。SEALED 隐藏胜负和数值，保留此前比分；ROUND_END 显示确认后的赢家，仍隐藏估时与误差；仅 RESULT 和 MATCH_WIN 可提供具体数值。界面不要直接用内部模型字段拼文案。
- 交接页按 OK 直接开始计时，不再进入二次准备页；双方成绩仍隐藏。整场胜利展示 3500 ms 或按 OK 后返回首页，必须在首页再次按 OK 才开启下一场。
- HOME 取消进行中或已完成的比赛，保留模式与随机流进度；模式切换只在首页生效。不持久化玩家历史，也不生成能力评级。

## 接入约束

`main.c` 已改为在按键回调中记录时间戳并非阻塞入队，由一个 LVGL 定时器先排空队列，再推进游戏 tick，明确 UI 归属和超时顺序。页面代次标记拒绝其他页面残留的输入；队列溢出取消比赛并提示重开，不编造结果。保留的硬件 demo 仍需验证这一分发改动没有回归。

新页面显式使用 Noto Sans SC 中文子集。[素材清单](../assets/README.zh_CN.md#time-duel-美术素材)记录字体许可、再生成命令和 222,720 字节常量 RGB565／RGB565A8 图像预算。源 PNG 不作为运行时依赖。其他 demo 保留公共主题；新页面右上角保留不遮挡的电量标识及不可用状态。

固件 UI 由 LVGL 任务操作，其他上下文必须显式持锁。音频和电量使用一个应用级常驻 worker，栈为 3072 字节，从不持有 UI 指针。单槽覆盖邮箱始终传递最新声音状态，避免静音后旧音乐排队重启。32 字节的纯合成器将原创旋律／低音循环与六种短音效混合到一个 256 字节 PCM 缓冲，不分配或保存整段录音。离开页面使排队音效的代次失效，并停止电量轮询；正在播放的音效每 128 个采样检查取消。UI 动画随对象删除，页面不遗留自有定时器或回调。其他 demo 保留原主题与菜单入口。

菜单默认选中 Challenge，OK 进入游戏。游戏首页 UP 切换双人／AI 模式，DOWN 一并开关音乐与音效，默认开启，音量为 75/100；OK 执行当前画面提示。长按 OK 一秒退出到保留的硬件菜单，这是固件容器边界，与浏览器仅返回游戏首页不同。核心也保留 HOME 取消接口，用于输入丢失。非计时阶段闲置 60 秒后亮度降到 15% 并停止音乐，下一次按键唤醒并恢复声音、不推进挑战。bootloader 的五秒上键钩子保持不变。

## 验证与下一步

2026-09-06 发布候选版已通过 ESP-IDF 5.5.3 完整门禁：应用 1,811,408 字节，校验后的合并镜像 1,876,944 字节。新增只读 `FAP_SCREENSHOT_V1` 服务，通过监听 LVGL flush，在 USB Serial/JTAG 上提供降采样后的 120 × 160 RGB565LE 画面，作为官方发布器的实机证据。原先的 240 × 320 原生静态帧缓冲因 DRAM 超出 15,536 字节而放弃；最终观察器方案保持在设备预算内。重新读取设备分区表并确认一致后，仅写入 `0x10000` 应用区，hash 校验通过；官方截图工具随后采集到真实游戏首页，完整固件、3:4 封面与实机截图均通过发布器校验。公开源码仓库为 <https://github.com/wuuli/ai-passport>，本次发布位于 `feature/time-duel` 分支；社区上传仍需先完成官方浏览器授权，并在提交前获得用户明确确认。`0x700000` 处既有 Recovery 镜像缺失状态未改变。

交接页改版已于 2026-09-06 同步至固件并安装：目标页和交接页复用相同的 192 x 105 时长卡片及 40 px 数字，交接页不再显示两名特工头像或 VS。ESP-IDF 5.5.3 完整门禁通过：应用 1,801,776 字节，校验后的合并镜像 1,867,312 字节。实际 LVGL 主机测试通过 20 组目标／交接卡片像素一致性检查、810 次页面渲染和 30 次退出重入；网页九项测试全部通过。重新读取设备分区表并确认一致后，仅写入 `0x10000` 应用区，hash 校验通过；串口重启确认 Display、Button、Audio、Battery 就绪。此前的电量刷新、声音和结算流程改动均保留。交接页实机观感与冷启动电量显示仍待确认；既有 Recovery 缺口未改变。

此前电量刷新修复于 2026-09-06 通过 ESP-IDF 5.5.3 完整门禁：应用 1,801,856 字节，校验后的合并镜像 1,867,392 字节。新增控制器回归先复现首页电量滞留，修复后通过，并通过地址／未定义行为 sanitizer；LVGL 主机测试完成 810 次渲染、30 次退出重入，确认仅电量区域像素更新且动画状态保持。重新读取设备分区表并确认一致后，仅写入 `0x10000` 应用区，hash 校验通过；串口重启确认 Display、Button、Audio、Battery 就绪。这是安装／启动证据，完整断电开机及首次进入的可见电量仍待用户验收。在该版本中，既有 Recovery 缺口与仅在网页中的交接页改版均未改变。

电量刷新独立于游戏状态切换：复用现有 LVGL tick，读取 worker 的原子缓存并调用 `duel_ui_set_battery`。该接口与整页渲染具有相同的 LVGL 归属／锁要求，将不可用值统一显示为 `--%`，忽略重复值，不改动游戏区对象。退出时先禁用 tick 再删 UI，新建屏幕重置显示缓存。静态门禁中的 `tests/test_demo_duel.c` 调用真实页面控制器，覆盖首次延迟读数、读取失败／恢复、计时与动画连续性、闲置唤醒、退出重入。LVGL 主机测试另检查电量标签以外像素不变、同值不触发重复刷新、对象及动画状态保持。这些检查不代表物理 I2C 或冷启动行为已验收。

2026-09-06 首版通过 ESP-IDF 5.5.3 完整门禁。当时应用占 1,800,960 字节，上限为 3,145,728 字节；校验后的合并镜像为 1,866,496 字节。USB 仅分段写入 bootloader、分区表和应用，三段写入 hash 均通过；未写 NVS、既有图片／音频数据、cardid 或 Recovery 地址。写入前已在本机备份原引导／分区表和 factory 应用；备份及原始设备日志不作为仓库产物。

纯模型在主机上占 80 字节；15 组测试覆盖 32 条计分比赛路径、连续 1000 次平局、5000 组相同种子的 AI 对照，AddressSanitizer 与 UndefinedBehaviorSanitizer 通过。实际 LVGL 9.5 主机测试现已完成 810 次页面渲染，包含平局结算，检查可见字形与屏幕边界、确认计时画面静止，并完成 30 次退出重入且内存池无泄漏。主机使用相同的 24 KiB LVGL 池及 20 行显示缓冲，池峰值为 18,072 字节。这是主机结果，不是真机峰值 RAM 实测。

锁定版本的托管组件就绪后，可选运行 UI 测试：

```bash
cmake -S tests/duel_ui -B /tmp/time-challenge-ui -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/time-challenge-ui -j 6
/tmp/time-challenge-ui/test_duel_ui
```

本机当前使用临时 SDK／工具目录 `/tmp/ai-passport-idf-v5.5.3` 和 `/tmp/ai-passport-idf-tools`。将 `IDF_TOOLS_PATH` 设为后者，source 前者的 `export.sh` 后运行 `./tools/validate.sh`；未更改全局 shell 配置。临时 SDK 可能在清理或重启后消失，需要长期使用时按环境搭建文档安装到持久目录。

真机验收需覆盖 3:0 与 3:2、连续平局、双方先手、忘记停止、持续按住 OK、输入过载、所有阶段取消／重入、AI 练习、音效关闭／失败、电量不可用，以及多次退出页面后堆内存不持续下降。

刷机前，该设备的原分区表没有 Recovery 条目，约定的 `0x700000` 起始 256 字节也全为擦除态。这是设备原有状态，并非本次刷写造成。新分区表和钩子保留该地址，但没有安装替代 Recovery。在获准恢复官方 Recovery 并通过实际测试前，不能宣称该设备五秒恢复入口或小程序安装验收通过。

## 真机反馈与优化版

用户反馈首版整体游玩正常，确认了基本真机可玩性，但不代表所有验收项均通过。用户提出的三项优化已实现：原创音乐及按键音、交接直接计时、下一场先回首页再开启。五局三胜不变，网页预览现已同步这些优化及后续封存确认流程，采用固件衍生素材，并单独标注暂停的演示画面；网页验证不替代实机验收。

首个优化版于 2026-09-06 通过完整门禁：应用 1,801,568 字节，合并镜像 1,867,104 字节。确认分区表与已装版本一致后，仅更新 `0x10000` 应用区，USB 写入 hash 校验通过；启动再次报告 Display、Button、Audio、Battery 就绪。既有 bootloader 和全部数据／保护区域均未修改。

更新后的核心测试在全部 32 条计分比赛路径中覆盖直接交接、定时／手动回首页，以及独立防抖的首页重开。音频测试覆盖音乐循环、静音、六种音效、抢占、分块一致性、输出幅度及 24 ms 开始音后的静音；核心和音频 sanitizer 测试通过。用户随后反馈能听到声音但偏小，并要求小回合结果明确确认后继续。当时默认音量由 40/100 调为 75/100，并让回合庆祝页和详细成绩页均等待 OK，通过了闲置一小时不推进的主机测试。后续澄清已取代这一回合页面顺序，见下文；I2S 有缓冲，主机静音测试不能证明声学零延迟。

此前音量／手动确认版已通过完整门禁：应用 1,801,536 字节，合并镜像 1,867,072 字节；仅应用区 USB 写入 hash 校验和四项外设启动检查通过，包含输入批次时间戳保护。用户随后反馈整体体验不错，按键音量已足够；希望背景音乐再大一点，并在确认之后才知道赢家。

本轮优化保留三个独立页面：成绩封存、回合庆祝、具体数值。先确认，才公布胜负和更新比分；1.5 秒动画结束自动进入数值页，下一回合仍需手动确认。仅将音乐 PCM 幅度增加 40%（约 2.9 dB），总音量保持 75/100，六种提示音的波形 hash 与修改前一致。主机测试覆盖确认前隐藏结果／保留旧比分、闲置不揭晓、动画时长／跳过、平局、AI、只加分一次、提示音不变及计时静音，均通过；本轮已通过 ESP-IDF 5.5.3 完整门禁：应用 1,801,792 字节，合并镜像 1,867,328 字节。重新读取连接设备的分区表并确认与构建一致后，仅写 `0x10000` 应用区，USB hash 校验通过；Display、Button、Audio、Battery 均启动成功。修正后的 UI 测试数据在封存时显示旧比分、确认后才显示新比分；最新 810 次主机渲染及 30 次退出重入检查通过。新揭晓流程和背景音乐平衡仍待用户实机确认。

下一步完成剩余真机验收矩阵，重点确认持续按键行为与最终背景音乐平衡，并通过获准流程恢复和验证官方 Recovery。发布构建、USB 写入与发布器检查通过，仍不能关闭这些硬件缺口。
