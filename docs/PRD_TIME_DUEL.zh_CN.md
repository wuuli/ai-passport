# 掐秒挑战（Time Challenge）— 产品需求文档

## 当前范围

两名玩家共用**同一台 AI Passport**，估算相同的目标时长。绝对误差较小者赢下回合，先赢三回合者赢得整场比赛。

[网页交互预览](../prototype/time-duel-v2.html)现已同步当前固件的界面与流程，包含后续试玩优化。[任务清单](TASKS_TIME_DUEL.zh_CN.md)区分实现状态与设备证据。本玩法无需设备通信，此前双机 BLE 设想已被取代。

交接页去掉双人 VS，复用目标页相同位置、40 px 数字字号的时长卡片。先手成绩仍封存，一次 OK 直接开始计时。固件与网页现已同步该布局；固件两个页面调用同一个时长卡片构建函数。

九步流程导航与五组情景在点选画面后暂停，并明确标注演示数据；按 OK 接着操作，播放按钮则恢复真实时长的阶段跳转。自由试玩使用共享 OK 键或 Space／Enter。网页同步封存确认、独立 1.5 秒回合动画、停留等待的数值结果、3.5 秒整场胜利后回首页，也模拟 60 秒闲置变暗和首次按键仅唤醒。浏览器字体、音频输出、示意电量值及硬件菜单边界不代表设备测量。使用 Node 22 及以上执行 `node --test tests/test_duel_preview.cjs`，检查网页流程与提示音 PCM 一致性。

## 已确认需求

- 双人比赛在同一台设备上进行，无需 NFC 或 BLE 配对。
- 目标从 1.0～6.0 秒中抽取，步进 0.5 秒。
- 每名玩家通过设备按键控制自己估时的开始与结束。
- 计时过程中不显示已过时间。
- 五局三胜，平局不占五个计分回合。
- 单回合获胜和整场胜利使用不同的庆祝动画。

## 交互基线

采用**轮流传递设备，共用 OK 键**。用户真机试玩确认基本流程正常，并要求交接直接开始、整场结束回首页，以及背景音乐和按键反馈。

板载上、下、OK 三个按键共用一个 ADC 分压电路，BSP 按互斥电压窗口识别按键，不能假定同时按两键能产生独立事件。轮流操作适配现有输入接口。

### 单回合流程

1. 公布目标与先手玩家，先手按 OK 开始。
2. 显示当前玩家和中性吉祥物，再按 OK 锁定成绩。
3. 暂不公开成绩，在交接页显示相同目标，提示将 Passport 交给下一位。
4. 下一位按 OK 立即开始计时，再按一次停止。不再单独确认准备，也不进入第二个目标页。
5. 双方完成后封存成绩，等待额外一次 OK 确认。确认前不公布赢家、估时、误差，也不更新比分、不播放胜负音效。
6. 确认后按 `abs(估时 - 目标)` 判胜并更新比分，播放独立的小回合胜利动画，平局使用中性展示。1.5 秒后自动进入双方估时、误差及比分页，OK 可跳过动画；不合并动画与数值页。详细成绩停留等待 OK，绝不自动开始下一回合。
7. 按 OK 继续。每次挑战交换先手，包括平局重赛；平局保留目标、比分和回合编号。
8. 一方先赢三局后，先展示最后一局的庆祝与成绩，再进入整场胜利界面。3.5 秒后自动返回游戏首页，也可按 OK 提前返回；仅在首页再次按 OK 才开始新比赛。保留双人／AI 模式。长按 OK 一秒退出到硬件菜单，浏览器明确以示意菜单呈现这一退出边界。

### 计时与公平性

- 交接与成绩封存期间均不公开双方估时。按 OK 确认后才揭晓胜负，庆祝结束后再显示具体数值。
- 估时期间没有倒计时、已过时间、进度条或可作为节拍器的周期动画。
- 未停止的挑战在 `目标 + 3 秒` 自动结束，以该时长作为成绩，并在结算中标明自动停止。
- 忽略 200 ms 防抖窗口内的重复按键。
- 固件应在 `BSP_BTN_PRESS` 时用 `esp_timer_get_time()` 记录时间戳，再通知游戏逻辑；回调中不进行音频或显示工作。
- 浏览器原型使用 `performance.now()`，估时取整到毫秒；浏览器结果不能证明真机计时精度。
- 传递设备和轮换先手可以减轻顺序影响，但不能阻止玩家观察对方的按键动作。

## 训练缘由

游戏名称为「掐秒挑战」，不另设课程副标题。「时间感训练」是游戏内容，整体围绕两名特工在训练营进行时间感比拼展开。

开场文案为：「两名特工，一场时间感训练的比拼。不看表，凭感觉，比谁掐得准。」两名特工共用一台终端，轮流完成相同目标时长；绝对误差较小者赢一轮，先赢三轮者赢得本场对抗。徽章只表示回合胜场，不代表军衔，也不另加成长系统。

具体任务属于时距产生：不借助已过时间显示，主动开始并结束一段指定时长。练习的是时长估计与动作时机，而非看到信号后尽快反应。成绩也受注意力与按键时机影响，不作为真实行动能力的认证，也不承诺广泛的认知能力提升。

所有目标时长的回合都统一显示「时间感训练」，不再映射虚构任务，也不附加行动剧情。揭晓目标后提示记住时长，OK 提示统一使用「开始计时」和「停止计时」。提前或延后相同时长，误差相同。

流程为训练简报与目标揭晓、掐秒挑战、成绩封存与交接、回合庆祝、训练报告和对抗结算。首页、按键提示、情景预览与两层结算统一使用训练语境。开场文案应在计时前即可读完，不增加打断挑战的过场或倒计时。单人练习沿用这一背景，对手为 AI 教官。

## 视觉与音效

浏览器原型采用《合金弹头》那种手绘感军事像素动画方向，不再使用简约几何街机图标。原创红头带与蓝贝雷帽特工、夕阳前哨、旧军绿色外壳、沙金色字体、锈红 OK 键构成统一风格；网页屏幕改为跟随固件布局，不额外叠加 CRT 特效。生成素材及提示词记录在[资源清单](../assets/README.zh_CN.md#time-duel-美术素材)。固件使用经过尺寸预算的衍生素材、中文子集字体和 LVGL 布局。右上角保留不遮挡装饰的电量标识，浏览器里的设备外壳与电量读数为示意。

- **计时期间：**特工保持待命姿态，场景和扫描线保持静止，不提供固定节拍的视觉或声音提示。
- **回合获胜：**胜方切换为举拳姿态，播放短暂冲击烟火、ROUND WIN 横幅盖章入场和比分跳动；平局使用中性的 DRAW 状态，不播放冲击烟火。
- **整场胜利：**点名本场训练对抗的优胜者，展示庆祝星形和最终比分，先返回首页，再开始下一场。
- **动画完成度：**原型使用每人两种插画姿态与分段 CSS 位移动画，并非已经完成的角色逐帧动画集；尊重系统减少动态效果偏好。
- **内存：**ESP32-C3 无 PSRAM，大尺寸源 PNG 仅用于浏览器设计，未链接到固件。设备使用一张 240 × 240 不透明 RGB565 背景和四个 80 × 112 透明 RGB565A8 姿态，合计 222,720 字节常量图像数据存于 Flash；用 `lv_anim` 位移实现动作，不使用全屏逐帧动画。
- **声音：**非计时阶段播放原创合成芯片音乐；有效按键、开始、停止、回合胜负和整场胜利都有短反馈音。进入计时即停止生成音乐、打断此前音效，仅保留一次 24 ms 开始提示音，估时过程中不播放节拍音乐。输出音量保持默认 75/100；仅将音乐 PCM 幅度提高 40%（约 2.9 dB），旋律为 1540、低音为 770，全部提示音波形与总音量设置均不变；首页 DOWN 一并开关音乐与音效；闲置变暗及退出时停止音乐。worker 以每块 128 个采样生成 16 kHz 单声道 PCM，不在输入回调或 LVGL 任务中操作音频。实际声学延迟和音量须真机试听；网页在用户首次操作后合成相同音乐和六种提示音 PCM 波形，不声称与设备扬声器音量相同。

## 单人练习

同一台设备支持 AI 对手。玩家完成挑战后，AI 独立生成估时，再统一结算。固件与原型均使用高斯误差模型，`sigma = 0.12 * 目标`。较小的系数表示更精准、更强的对手，难度档位待试玩校准。

## 固件实现方向

- `main/duel_clock.c/h`：独立于硬件的计时状态机、交接、判定、比分与 AI 模型。
- `main/duel_ui.c`：共享屏幕的 LVGL 展示及两层庆祝动画。
- `main/demo_duel.c`：页面生命周期、按键事件、音频分发与演示页注册。
- `main/duel_io.c/h`、`main/duel_sound.c/h`：worker 音频／电量 I/O，以及独立于硬件、不分配内存的音乐与音效合成器。
- `tests/test_duel_sound.c`、`tests/duel_ui/`：音乐、静音、音效抢占、计时静音，以及实际 LVGL 字形／布局、计时画面静止及退出重入测试。
- `tests/test_duel_clock.c`：覆盖状态迁移、平局、超时、轮换先手、提前结束比赛与带种子的 AI 行为。
- 不需要游戏专用 BLE 协议、配对任务或 central 角色配置变更。

保留 3 MB 应用限制、受保护的 cardid/Recovery 分区、现有长按返回约定和上键五秒 Recovery 入口；删除界面前停止页面所属任务、回调和定时器。

## 验收目标

以下是实现要求，不是已完成的验证结果。

- 纯游戏模型和带种子的 AI 行为通过 host 测试。
- 完整固件门禁通过，分区和 Recovery 兼容性保持不变。
- 在一台真机上完成双人比赛，包含交接时隐藏成绩、平局、忘记停止时自动结束、两层庆祝、再战及长按退出。
- 在实际设备上检查按键时序、屏幕可读性、音效及内存占用。

## 待评审事项

1. 去掉二次确认后，复测真机交接操作是否顺畅。
2. 真机试玩后调整目标范围及 AI 难度。
3. 在 240 × 320 屏幕上调整动画姿态、提示时长与信息密度。
