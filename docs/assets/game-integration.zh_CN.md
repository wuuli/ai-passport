# 游戏与上游基线的集成

此衍生分支将上游 `1051209` 与 8 号出口、掐秒挑战集成。两个游戏保留玩法、素材和可移植 C 内核，导航与上游硬件测试应用分开。

## 入口与操作

默认构建使用 `main/game_main.c`，启动显示 8 号出口标题页。走廊游玩中长按 OK 回标题，在标题页再长按 OK 进入游戏选择。顶部键与中部键选择 8 号出口或掐秒挑战，短按 OK 进入。掐秒挑战中长按 OK 回游戏选择。

选择页和两个游戏均使用独立 LVGL 界面。`CONFIG_PASSPORT_HARDWARE_DEMO=y` 切换为上游 `main/main.c` 诊断应用；硬件测试页面是参考代码，不属于游戏导航。

按键回调只入队带时间戳的事件，由一个 LVGL 定时器消费并推进当前游戏；页面切换递增代数，旧队列事件不会操作新页面。输入溢出会停止当前游戏。BSP 按键任务不调用游戏 UI。电池/音频工作任务持续于应用生命周期，仅共享原子数据，不保留页面指针。

网页预览为一款游戏一个独立页面：[8号出口](http://127.0.0.1:8098/)和[掐秒挑战](http://127.0.0.1:8098/time-duel-v2.html)。长按 OK 返回该游戏的开始界面；上述固件选择器不再额外模拟为一个 Demo 页面。

## 显示与安装兼容性

集成采用上游显示初始化回滚、圆角遮罩、80 MHz LCD SPI 和单个 40 行 LVGL 绘制缓冲。相比此前双缓冲少用 19,200 字节；实际帧节奏与显示效果仍需真机测量。两个游戏的状态与电量文字向内留边，避免被 30 像素圆角遮罩裁切；网页外壳也展示相同圆角安全区。

本分支明确保留现有 3 MB factory 分区、`cardid`、Recovery 区域和上键引导钩子。这是本应用的兼容选择，不是上游模板要求。钩子不会安装 Recovery 镜像。布局门禁按实际分区表校验；刷写无需先备份原固件。不能未经核对就认定旧设备布局兼容，也不能把整片擦除当作常规安装步骤。

## Demo 与真机验收

遵循[共享 C/Wasm 验收 SOP](../development/engineering/game-demo-to-device-acceptance.zh_CN.md)。8 号出口共享模型和渲染器；掐秒挑战共享 C 模型，浏览器页面作为 LVGL 界面的视觉参考。网页一致性不证明真机字体、内存余量、实体按键响应、声音或显示帧节奏。

改变后的入口/退出路径、游戏重进、电量显示、上游显示变更和两个完整玩法流程均需重新真机验收。旧设备报告只描述当时的候选版本，不代表此次集成通过。

## 集成候选版本检查（2026-09-27）

静态／主机测试及 ESP-IDF 5.5.3 固件／分区门禁通过。应用为 1,502,336 字节，合并镜像为 1,567,872 字节。合并镜像 SHA-256 为 `a388aff41e3f5da2663f44f877aa5ac2fd14f2b76403d46b66664fa616536fb4`，对应 ELF／MAP 与清单保存在 `build/firmware/<sha256>/`。这是本地提交前构建的身份，不代表已安装或已发布版本。

调度测试覆盖导航、过期输入、队列溢出及队列取空后新到的按键：tick 使用批次开始时间，避免越过该排队按键。两个游戏的原生 C／Wasm 轨迹对比通过。本次集成的真机测试为 **NOT RUN**。
