# 8号出口固件网页预览

主[预览](http://127.0.0.1:8098/)通过 WebAssembly 运行当前固件的游戏与渲染代码。请先启动下文的本地服务；直接用 `file://` 打开无法加载 WebAssembly 模块和素材。此预览替代独立 JavaScript 原型；早期 JavaScript 原型运行时已停用归档，角色烘焙工具与帧包校验测试继续保留。

## 共用代码与素材

- `main/corridor_game.c` 和 `main/corridor_render.c` 原样编译。三键行走、圆弧拐角、斜向可见物件对中、按进入侧判定、走错归零和连续八次通关均使用同一份 C 实现。
- 网页加载同一份 312,689 字节的 `commuter-device.bin`；调色板、人物查表和告示数据由固件 include 编入。墙面采用浅灰纯色，保留距离明暗和踢脚线，不使用墙砖查表或 PNG 图集。横向连接通道墙面（`side >= 2`）暗一级以保证拐角明暗对比。原生 C 与 Wasm 像素级一致性已通过；64 组同视点接缝与双外拐角对比回归通过。包含此拐角区分优化的当前固件已于 2026-09-27 安装到真机，并通过串口截取到开机直达标题页的画面。
- 生成的 `presentation.json` 提取 16px 正文与四字形 30px 标题字体，并与 `demo_corridor.c` 校验标题／状态文字。Canvas 外壳按 RGB565 量化展开索引画面，以原生 240×320 绘制暗色开场、日光色通关界面和 HUD。开场按实体位置标明顶部键、中部键、底部 OK 键，并说明拐角自动转向停步；开头与结尾的主操作均位于 y=252、返回提示位于 y=287。主操作在 800ms 内渐显一次后保持稳定。UI 调整不改变楼梯与出口渲染。
- `manifest.json` 保存源码与生成产物的 SHA-256；加载时核验 Wasm、界面数据和人物素材，静态门禁拒绝源码修改后未重建的旧产物。

薄层 C 桥接只暴露输入、推进、输出及显式评审样例。网页层处理指针／键盘、可见性、加载、显示和开发工具，不再独立实现游戏状态机。

## 运行与重建

本地预览检查需要 Python 3.10+、Node.js 18+ 和 C11 编译器。查看已生成的预览只需要现代浏览器及 HTTP 服务，无需 SDK。

```bash
python3 tools/serve_corridor_web.py --port 8098
# Open http://127.0.0.1:8098/
python3 tools/build_corridor_web.py --check
node tests/test_corridor_web.mjs
```

服务仅监听回环地址，只提供预览与素材子目录。端口已被占用时不要再启动第二个服务。

修改清单内的原生源码或素材后，使用官方 [WASI SDK](https://github.com/WebAssembly/wasi-sdk/releases) 重建（已验证 34.0）：

```bash
python3 tools/build_corridor_web.py --sdk /path/to/wasi-sdk
./tools/validate.sh --static
# Activate ESP-IDF 5.5.3 before the complete gate:
./tools/validate.sh
```

`corridor.wasm`、`presentation.json` 和 `manifest.json` 必须配套保存。运行库许可随模块保存在 `prototype/exit-corridor/firmware/`；人物来源见[素材说明](../assets/images/exit-corridor/README.zh_CN.md)。

## 操作与评审

UP／上箭头按下向左转 45°，DOWN／下箭头按下向右转 45°，短按 OK／空格／Enter 会从标题页进入，或在游戏中于松开时切换走停。长按 OK 一秒返回网页标题；同时仅接受一个按键。失焦、隐藏标签页和取消触摸均停止行走。

开发评审默认收起；展开时暂停并显示答案。可选择全部九种正常／异常场景、门楣正向与折返对照视角、用户反馈的 45° 海报位置、拐角及边界／最后一轮位置。继续观察恢复模拟，也可按 OK 开始行走。回到盲玩会从零开始，注入的样例不会带入盲玩。放大仅改变 CSS 显示尺寸。

自动拐弯过程中，OK 暂停／继续圆弧。左右键取消辅助并停止位移；目标朝向先取最近的 45° 方向，再叠加所按方向的转角，由相机缓动转向。按键瞬间的位置和显示视角不会跳变。普通手动转向仍是相对当前方向转 45°。

跨越通道边界时，游戏分数照常立即判定。左上角数字保留上一轮结果，等相机靠近中线并转向下一段走廊后才更新，避免先于场景内出口牌透露新编号。手动转向也能触发显示；显示后即使回头，数字也不会倒退。

## 走出通道

第八次正确判断进入 `EC_EXITING`（3），而不是直接进入 `EC_CLEARED`（2）。新通道保留跨界位置和拐角辅助，显示出口 8，并通向短楼梯与自然光。方向键仍转 45° 并停步，OK 切换行走。进度固定为 8，不再选择异常，回头不会触发新的判断。走上楼梯，再经过两米平台到达出口门口，才显示持续保留的通关面板；再单独按 OK 才开始停止行走的出口 0。这里是面向设备的“走出通道”体验适配，不是原版结尾的逐帧复刻。

快速受控评审可选正常场景加第 7 轮前方跨界，或红灯加第 7 轮后方跨界。按 OK 跨界，等待辅助拐角正对台阶停下，再按 OK 走出；途中随时可以暂停和观察。出口几何由同一套内存有界的 C 渲染器生成，不另分配帧缓冲或楼梯纹理。

## 验证与边界

2026-09-20 拐角复验通过可见网页控件检查了四个进入方向，停点分别为 (0.85, -26.8, 90°)、(-0.85, 2.8, -90°)、(0, 1.95, 0°) 和 (0, -25.95, 180°)，均位于下一段通道中心线上并面向该段。审查另复现了圆弧中途手动接管后朝向偏离网格的问题，已在共用 C 逻辑修正，并补充原生及 Wasm 回归测试。实体键时序与真机运动体感仍待硬件验收。

加入出口终段之前，2026-09-20 的受控网页验收确认了旧版即时通关面板、主动重玩和红灯前进的 7→0 失败。该历史检查不覆盖新增楼梯。真机专有的漏刷新另由 `tests/test_corridor_demo.c` 调用实际固件 tick 与 UI 桩覆盖，现包含出口段持续渲染和限帧时走到出口门口通关；Canvas 显示正常不能替代真机 LVGL 刷新验收。

2026-09-20 更新后的原生 C 与 Wasm 对照使用 5,729 条指令、163 个采样画面，包含 24 组拐弯中途暂停后接管、再从原地恢复辅助的用例。12,518,400 个索引像素中有 2 个不同，最大颜色通道差值为 2/255，状态最大误差为 1.20e-7。覆盖换轮、两个进入方向、可行走出口段与门口通关、转向、暂停和观察。这是采样等价检查，不代表所有可能操作都已穷尽。

网页交互验证确认：斜看海报转正后停在 X=0、Z=-20、90°；正常 7→8 通关及重玩；异常前进 7→0；异常折返 0→1。旧 WebGL 地址已加载共用固件预览。

新结尾已通过可见评审控件和真实按键验收：正常前进与红灯折返均进入出口 8，经辅助拐角后继续走到各自出口门口才通关。另行检查了楼梯中段 45° 观察、主动重玩后停在出口 0，以及错误前进的 7→0。默认桌面视口和 390x844 截图确认场景与三键无重叠。预览停在台阶前供用户验收。这些是受控样例，不是重新盲玩八轮。静态／主机测试和 ESP-IDF 固件门禁通过，渲染器 ASan／UBSan 检查通过。未刷写设备，楼梯真机帧率、体感与 RAM 余量仍待验证。

网页不模拟 ESP32 内存压力、SPI／DMA 时序、实体 ADC 去抖、LVGL 合成、电量或设备菜单。电量为 `--`，长按 OK 回到预览标题。网页循环最多提交 20 帧／秒，性能显示明确标注非真机测量；原生帧缓冲对比不包含 Canvas HUD 合成。网页构建不修改或刷写设备固件。
